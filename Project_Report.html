Project Description

FarmVerse is a single, unified platform that replaces the fragmented digital experience of Indian farmers. Prior to this platform, a farmer would use one app for weather, a different website for crop prices, a WhatsApp group for pest advice, and an unregulated channel for selling produce. FarmVerse consolidates all these functions into a single, secure, AI-powered ecosystem.

Three-Tier Architecture Approach

1

Presentation Tier — Lightweight Frontend

A responsive, lightweight frontend using native HTML5, CSS3, and Vanilla JavaScript. The deliberate choice to avoid heavy frameworks like React ensures lightning-fast load times for farmers with low-bandwidth rural internet connections.

↓
2

Application Tier — Spring Boot REST API

A robust Spring Boot 4.x backend with 9 specialized REST Controllers exposing a secure JSON API. Spring Security with JWT ensures only authenticated users access protected resources, with role-based separation between Farmers and Admins.

↓
3

Data Tier — MongoDB Atlas (Cloud NoSQL)

MongoDB Atlas, a cloud-hosted NoSQL document database, stores all platform data in a flexible document format, making it easy to evolve the data model as new features are added without requiring database migrations.

Real-World Impact

Democratization of AI

By embedding Google Gemini AI directly into the farmer's dashboard, FarmVerse makes cutting-edge AI technology accessible to rural farmers who previously had no access to such tools.

Market Transparency

The digital marketplace eliminates middlemen and allows farmers to list produce directly for buyers at their own prices, potentially increasing farmer income significantly.

Food Security

By helping farmers identify crop diseases early and plan their sowing seasons correctly, the platform directly contributes to improving agricultural yield and national food security.

System Architecture

End-to-End Data Flow (AI Advisory Example)

1

Farmer Input (Browser)

Farmer types a question in dashboard.html. Vanilla JavaScript captures the input and prepares an HTTP POST request.

↓
2

HTTP Request with JWT

JavaScript sends POST to /api/ai/chat with the Authorization: Bearer {token} header attached.

↓
3

JwtAuthenticationFilter Intercepts

Validates the JWT signature and extracts the user's email. Sets the Authentication context in Spring's SecurityContextHolder.

↓
4

AIController Processes Request

Injects system prompt ("You are an expert agricultural advisor..."), constructs the Gemini API request payload, and loads GEMINI_API_KEY from environment variables.

↓
5

Google Gemini API (with Retry Logic)

RestTemplate sends the request to Google. If HTTP 503 is received, the retry loop waits 1.5s and tries again — up to 3 times total.

↓
6

Response and Logging

AI response extracted from Gemini JSON, logged to MongoDB advisory_history collection, and returned to the frontend for display.

Module-Wise Feature Details

🔐

Module 1: Authentication & Security System

AuthController.java | JwtService.java | SecurityConfig.java

Manages user registration, login, and JWT token issuance. Ensures each user only accesses resources appropriate to their role.

  • BCrypt password hashing — raw passwords are never stored
  • JWT generation with HMAC-SHA256 digital signature (24-hour validity)
  • Role-based access control: USER vs. ADMIN
  • Account suspension check (HTTP 403 returned even with correct credentials)
  • Duplicate email detection with clear error messages during registration
🤖

Module 2: AI Agricultural Advisory System

AIController.java | AdvisoryHistoryService.java | AppConfig.java

Integrates Google Gemini 3.6 Flash LLM for real-time, contextual crop management advice. The most technically sophisticated module in the platform.

  • System Prompt Injection: Constrains AI to agricultural topics only
  • Retry Mechanism: Custom loop — 3 retries with 1.5s delay for HTTP 503 errors
  • API Key Security: GEMINI_API_KEY loaded from system environment variables via @Value
  • Advisory History Logging: Every interaction saved to MongoDB with user email, query, response, and timestamp
  • Topics covered: Fertilizers, irrigation, organic practices, pest prevention, crop rotation
🔬

Module 3: Computer-Vision Pest & Disease Detector

PestController.java | Gemini Vision API

Allows farmers to upload a photograph of a diseased crop leaf. Processed using Google Gemini's multimodal (vision + text) capability.

  • Supports JPG, PNG, WEBP image formats
  • Detected pest/disease name (e.g., "Fall Armyworm", "Leaf Blight")
  • Severity assessment and chemical/organic remedy recommendations
  • Dosage and application timing provided
  • Result automatically logged to Advisory History for future reference
🏪

Module 4: Digital Farmer's Marketplace

MarketplaceController.java | AdminMarketplaceController.java

A direct-to-buyer trading platform with an Admin moderation workflow to prevent fraudulent or low-quality listings.

  • Categories: Crop, Vegetable, Fruit, Fertilizer, Equipment
  • Listing lifecycle: PENDING → APPROVED/REJECTED → SOLD
  • Buyer-seller dispute filing and Admin resolution system
  • Organic Certification badge support for verified produce
  • Location-based listing with quantity and unit price details
📅

Module 5: Crop Sowing Calendar

CropCalendarController.java | Admin CRUD

Visual, data-driven reference for farmers to plan sowing and harvesting activities by season and crop type.

  • Kharif (June-Oct): Rice, Maize, Mango, Cotton, Groundnut
  • Rabi (Oct-Mar): Tomato, Cucumber, Chickpea, Mustard, Barley
  • Summer (Mar-Jun): Okra, Watermelon, Muskmelon, Moong Dal
  • Farmers can submit "Suggest a Crop" requests via the Admin moderation queue
  • Admins have full CRUD control over calendar entries from the Command Center
🎮

Module 6: Gamification Engine

UserController.java | /api/user/sync

Applies game design psychology to drive consistent farmer engagement and behavioral adoption of good farming practices.

  • Daily Missions: "Log Soil Moisture" (+10 XP), "Ask AI" (+15 XP), "Browse Marketplace" (+5 XP)
  • Leveling System: Level 1 (Seed) → Level 2 (Growing) → Level 3 (Expert) → Level 4 (Master)
  • Village Leaderboard: Regional rankings by XP encouraging healthy competition
  • Achievements: Unlockable badges for milestones (First Harvest, AI Expert, Market Veteran)
  • XP and mission state persisted to MongoDB via /api/user/sync on every change
👨‍💼

Module 7: Admin Command Center

AdminController.java | AdminMarketplaceController.java

A completely separate, dark-themed dashboard accessible only to ADMIN role users, providing centralized platform oversight.

  • Overview Dashboard: Live user counts (13 total, 10 farmers, 15 active) pulled from MongoDB
  • User Management: Full table with role change (Farmer/Vet/Admin) and suspend functionality
  • Marketplace Moderation: Filter by status (Pending/Approved/Rejected), one-click approve/reject
  • Dispute Resolution: Mark disputes OPEN → RESOLVED or DISMISSED
  • Live Activity Feed: Real-time log of logins, registrations, JWT refreshes, and listing submissions

Security Implementation

Multi-Layer Defence-in-Depth Architecture

L1

CORS Filter

CorsConfigurationSource allows frontend JavaScript (running in browser) to make API calls to the backend without being blocked by browser Same-Origin Policy.

↓
L2

JWT Authentication Filter

JwtAuthenticationFilter extends OncePerRequestFilter — intercepts every HTTP request, reads the Authorization header, validates JWT signature using HMAC-SHA256, and populates SecurityContextHolder.

↓
L3

SecurityFilterChain (Role-Based Access Control)

Public: /api/auth/**, /api/marketplace/**, static files. Admin-only: /api/admin/** (hasRole("ADMIN")). All others: require any valid JWT.

↓
L4

BCrypt Password Hashing

All passwords are hashed using BCryptPasswordEncoder (cost factor 10) before being stored in MongoDB. Raw passwords are never persisted anywhere.

↓
L5

Account Suspension Check

AuthController checks user.isSuspended() AFTER successful credential validation. Suspended users receive HTTP 403 Forbidden even with correct credentials.

Why JWT instead of Session Cookies?

JWT makes the backend completely stateless — the server does not store session data in RAM. This means: (1) It scales to unlimited users without memory issues, (2) It works seamlessly with future Android/iOS apps, (3) Multiple load-balanced servers can validate any JWT without shared session storage.

Retry Logic Flow

MAX_RETRIES = 3
RETRY_DELAY = 1500ms

Attempt 1 → Call Google Gemini API
  ✅ Success → Extract text → Log to MongoDB → Return to frontend
  ❌ 503 Error → Wait 1.5 seconds

Attempt 2 → Retry Google Gemini API
  ✅ Success → Extract text → Log to MongoDB → Return to frontend
  ❌ 503 Error → Wait 1.5 seconds

Attempt 3 → Final retry
  ✅ Success → Extract text → Log to MongoDB → Return to frontend
  ❌ 503 Error → Return: "The AI is experiencing high demand. Please try again shortly."

Key Code Snippets

1. JWT Authentication (AuthController.java)

@PostMapping("/login")
public ResponseEntity<AuthResponse> login(@Valid @RequestBody LoginRequest request) {

    // Validates credentials (throws BadCredentialsException if wrong)
    authenticationManager.authenticate(
        new UsernamePasswordAuthenticationToken(request.getEmail(), request.getPassword())
    );

    User user = userService.findByEmail(request.getEmail());

    // Security: Block suspended accounts even with correct credentials
    if (user.isSuspended()) {
        return ResponseEntity.status(403).body(new AuthResponse("Account Suspended", "NONE"));
    }

    // Generate stateless JWT token signed with HMAC-SHA256
    String token = jwtService.generateToken(user.getEmail());
    return ResponseEntity.ok(new AuthResponse(token, user.getRole()));
}

2. Google Gemini AI with Retry Logic (AIController.java)

// Custom retry loop — handles temporary Google server overload (HTTP 503)
int maxRetries = 3;
for (int attempt = 1; attempt <= maxRetries; attempt++) {
    try {
        ResponseEntity<Map> response = restTemplate.exchange(
            url, HttpMethod.POST, entity, Map.class
        );
        Map<String, Object> body = response.getBody();

        if (body != null && body.containsKey("candidates")) {
            return extractTextFromGeminiResponse(body); // ✅ Success
        }
    } catch (Exception e) {
        System.err.println("Gemini API attempt " + attempt + " failed: " + e.getMessage());
        if (attempt < maxRetries) {
            Thread.sleep(1500); // Wait 1.5 seconds before retry
        } else {
            return "The AI is currently experiencing high demand. Please try again! 🌱";
        }
    }
}

3. Spring Security Filter Chain (SecurityConfig.java)

@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())  // Stateless API — no CSRF needed
        .cors(cors -> cors.configurationSource(corsConfigurationSource()))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers(
                "/", "/*.html", "/*.css", "/*.js",
                "/api/auth/**", "/api/marketplace/**", "/api/crop-calendar/**"
            ).permitAll()
            .requestMatchers("/api/admin/**").hasRole("ADMIN") // Admin-only guard
            .anyRequest().authenticated()
        )
        .sessionManagement(s ->
            s.sessionCreationPolicy(SessionCreationPolicy.STATELESS) // No server sessions
        )
        .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);

    return http.build();
}

5. Gamification XP Sync Endpoint (UserController.java)

/** POST /api/user/sync — Save XP, level, and mission checkbox state to MongoDB */
@PostMapping("/sync")
public ResponseEntity<ApiResponse> syncUserData(@RequestBody UserSyncDto syncDto) {

    // Get the currently logged-in user from JWT Security Context
    Authentication auth = SecurityContextHolder.getContext().getAuthentication();
    User user = userService.findByEmail(auth.getName());

    if (user == null) {
        return ResponseEntity.status(401).body(new ApiResponse("Unauthorized"));
    }

    // Update gamification fields from frontend
    user.setXp(syncDto.getXp());
    user.setLevel(syncDto.getLevel());
    user.setMissionsState(syncDto.getMissionsState());

    // Persist to MongoDB Atlas
    userService.saveUser(user);

    return ResponseEntity.ok(new ApiResponse("Data synced successfully"));
}

Challenges Faced & Resolutions

ChallengeProblemResolutionStatus
AI API Deprecation Google deprecated the older Gemini endpoint, causing HTTP 404 errors for all AI requests Updated AIController to use the latest Gemini 3.6 Flash endpoint. Externalized URL to configuration for future-proofing. ✅ RESOLVED
HTTP 503 AI Errors Intermittent Google server overload caused the AI chatbot to crash with error messages Engineered a custom 3-retry loop with 1.5s delay. Only after all 3 failures does it return a friendly error message. ✅ RESOLVED
Credential Security Hardcoded MongoDB password and Gemini API key in source code posed a critical security risk Moved all secrets to system environment variables. Spring @Value injects them at runtime. Never in source code. ✅ RESOLVED
Frontend Route Guarding Users could navigate directly to admin-dashboard.html via URL, bypassing the login check Added JavaScript session guards on page load that check localStorage for JWT and redirect unauthorized users. ✅ RESOLVED
Low-Bandwidth Performance Heavy frontend frameworks (React, Angular) would cause slow load times for rural farmers with weak internet Decided to use only native HTML, CSS, and Vanilla JavaScript — keeping all pages lightweight and fast-loading. ✅ RESOLVED
